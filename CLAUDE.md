# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A single-user desktop dashboard that captures snapshots of the stock market and routes them to a chosen AI (Claude / OpenAI / local OpenAI-compatible endpoint) for observations framed by a named trading style and per-snapshot objective. Strictly observational — no broker write path. Runs entirely in Docker Compose.

The design lives in `docs/superpowers/specs/2026-04-16-ai-dashboard-design.md`. Milestone plans live in `docs/superpowers/plans/`. Both are load-bearing — read the relevant spec section before adding a feature, and read the active milestone plan before starting new implementation work.

Milestones M1 (`m1-skeleton`) → M10 (`m10-ai-platform-v25`) → M12 (`m12-analytics`) → M14 (resident analyst) → M15 (strategist: `regime` / `book` / `warroom` / `desk`) are **all shipped** — each milestone has its own plan in `docs/superpowers/plans/` (M15 specs under `docs/superpowers/specs/2026-06-01-m15-*`). Several post-M12 features ship without milestone tags (free data sources, prediction ledger, morning briefing, scorecard, semantic recall).

## Architecture big picture

**Six-service compose stack** (dev): `web` (Django + DRF + Channels via Daphne), `worker` (Celery), `beat` (Celery beat with `django_celery_beat.schedulers:DatabaseScheduler`), `redis` (broker + Channels layer + cache), `db` (Postgres 16), `frontend` (Vite dev server). Everything binds to `127.0.0.1` only.

**Django project** is `backend/config/` with settings split into `base.py` / `dev.py` / `prod.py`. Apps live under `backend/apps/<name>/` and are imported as `apps.<name>` (PYTHONPATH is `/app/backend` inside containers). Celery app lives at `config.celery` and is re-exported from `config/__init__.py` so `@shared_task` discovery works. Channels routing lives at `config.routing` and is mounted by `config.asgi`. Celery task packages are listed **explicitly** in `config/celery.py` (not autodiscovered) — a past silent-failure made autodiscovery untrustworthy; add new task modules to that list.

**App roster** (`backend/apps/` — 27 apps): `core` (health, base consumer, logging, `MOCK_EXTERNAL` flag, `SystemSettings` + `runtime_config()`), `market` (Schwab client + free fallback providers under `services/`, orchestrated by `services/fallback.py`; quotes/OHLC/chain/news/macro/filings/treasury models, cache; `returns.py` shared forward-return helpers), `snapshots` (capture services + token budget, `stamp_payload_tokens`), `ai` (providers, router, catalog, cost calc), `threads` (message model, consumer, compare endpoint, per-branch `cost` event, Decision Coach `coach.py`), `costs` (per-provider + per-model + per-thread aggregation, daily/monthly caps, CSV export, snapshot drill-down), `profiles` (trading-style profiles + `AgentPreset` model with four seeded builtins), `secrets` (encrypted credential storage + Schwab OAuth + data-source API keys; cost caps; guarded accessor `credentials.py::decrypt_token`), `observer` (schedules + notifications + timeline), `triggers` (evaluator + DSL + firings), `backups` (pg_dump task + rotation + DRF ViewSet), `export` (async zip bundles of threads/snapshots/observations/triggers/profiles/watchlists), `thesis` (theses + post-mortems + decision journal; `/api/theses/` + `/api/journal/`), `analytics` (nine on-demand aggregations — see the analytics bullet below), `recall` (semantic + keyword search over all documents; pgvector index feeding the Coach), `briefing` (daily Morning Briefing assembly + AI synthesis), `files` (Anthropic Files API proxy), `aieval` (offline eval/calibration harness, `EvalRun`), `dashboard` (`GET /api/dashboard/` command-centre rollup), `portfolio` (manual position tracking + realized/unrealized P&L, thesis-linked — API-complete; page not yet routed), `predictions` (M13 — the AI's own auto-extracted, auto-resolving forecasts), `lessons` (M14 — distilled recurring post-mortem lessons feeding the Coach), `coverage` (M14 — a living, version-controlled per-ticker "house view" the AI revises with a reason), `regime` (M15 — append-only market-regime readings; latest row = current; `regime.refresh` beat), `book` (M15 — daily whole-book risk reading / "Book X-ray"; append-only `BookSnapshot`; `book.snapshot_daily` beat), `warroom` (M15 — multi-agent "courtroom" debate; `WarRoomRun` spins up a thread and streams over `thread.<id>` via `run_ai_on_message`), `desk` (M15 — agentic anomaly-sweep desk; `DeskEntry`).

**Adding a Django app:** create `backend/apps/<name>/` with `__init__.py`, `apps.py` (`AppConfig` with `name = "apps.<name>"`, short `label`), `urls.py`, `views.py` (as needed). Add `"apps.<name>"` to `INSTALLED_APPS` in `config/settings/base.py`. Include in `config/urls.py` as `path("api/<name>/", include("apps.<name>.urls"))`. WebSocket consumers go in `consumers.py`; register routes in `config/routing.py`.

**Realtime channels (WS)** — three conventions documented in the design spec §3.3:
- `user.<id>.notifications` — trigger fires, observer completions, backup/export events, errors
- `thread.<id>` — streaming AI tokens, message lifecycle; carries `message_started` / `text_delta` / `message_done` / `cost` / `error` events. `cost` is emitted after `message_done` and carries `parent_message_id` so Compare UI can route it to the right branch tab.
- `snapshot.<id>` — per-section capture progress

Each is a Channels group. Groups are joined in `connect()` and left in `disconnect()`. See `apps/core/consumers.py` for the minimal reference consumer.

**`thread.<id>` reconnect replay buffer is wired end-to-end.** `apps/threads/event_log.py` stamps every `thread.<id>` event with a per-thread monotonic `seq` (via Redis `INCR`), keeps the last 256 events in a capped Redis list (`thread:<id>:wslog`, 1-hour TTL), and `ThreadConsumer.connect()` replays events with `seq > since` when `?since=<seq>` is present in the WS URL. `WebSocketProvider.tsx` tracks the last-received `seq` per channel and appends `?since=<seq>` **on reconnect** (first connect sends none — the presence of a tracked seq IS the reconnect signal), so events emitted during a drop are replayed. Seq-less channels (snapshots/notifications) never set a cursor and so never send `?since=`; a deliberate teardown clears the per-channel cursor so a later re-subscribe is a fresh first-connect (live tail), not a replay since you left.

**Provider abstraction:** `apps/ai/providers/base.py` defines the `Provider` protocol; implementations are `ClaudeProvider` (anthropic SDK), `OpenAIProvider`, and `LocalProvider` (openai SDK to user-configured base URL). `run()` emits a normalized event union (`text_delta | image_ref | usage | done | error`) so the WebSocket consumer is provider-agnostic. Selection flows through `apps/ai/router.py` (precedence rules) and `get_provider()` factory; do not instantiate providers directly from views/tasks. Cost calculation lives in `apps/ai/cost.py` against `apps/ai/catalog.py` (per-model pricing entries). See design spec §6.

**Multi-provider fan-out:** `POST /api/threads/<id>/compare` runs the same prompt across multiple provider+model pairs in parallel, streaming each into its own branch. Stopping a stream: `POST /api/threads/<id>/messages/<msg_id>/stop` sets a Redis stop flag (`apps/threads/stop.py`); the streaming loop in `apps/threads/tasks.py` polls it (~every 0.25s) and closes the provider generator (`gen.aclose()`), aborting the upstream stream so generation and billing actually halt — it does not merely discard the final write.

**Capture pipeline:** `apps/snapshots/services/` fills a snapshot's sections inside a single `snapshots.capture` Celery task — a **synchronous loop** over `snap.includes` calling per-section fetchers (quotes, chain, ohlc, positions, breadth, news, image, plus the opt-in `macro`/FRED, `filings`/EDGAR+Form 4, `treasury`/yield-curve, `events`/forward-calendar, and overnight-futures sections; market fetchers fall back to a free provider when Schwab isn't connected). A section that raises is caught and marked `failed` (no per-section subtask, no automatic retry); partial failures are acceptable and missing sections are explicitly marked in the AI payload. Per-section progress is broadcast over `snapshot.<id>`. `apps/snapshots/token_budget.py` trims the payload before it hits the model; `stamp_payload_tokens` records per-section token counts on `SnapshotSection.payload_tokens` for the cost drill-down. (Design spec §5 describes a parallel Celery fan-out with a `finalize_snapshot` chord; the implementation is the simpler synchronous loop — prefer this description.)

**Event-trigger evaluator:** A Celery beat-scheduled task (`evaluate_triggers`) runs every ~10s — NOT a long-running worker process and NOT a separate container. Condition DSL is JSON with top-level `all/any/not` and leaves like `{"metric", "ticker", "op", "value", "window"}`. See spec §4.8 and §7.2.

**Frontend routing:** All user-facing routes nest under a shared `<AppLayout>` — `TopNav` + `SideNav` + `NotificationBell` + `ConnectionStatusDot` + `Breadcrumbs`. Only `/render/chart` bypasses the layout. Add new routes as children of the parent route in `frontend/src/router.tsx` and give each a `handle: { crumb: "..." }` (string or function `({params}) => string`). Keyboard shortcuts are `g <x>` — see `frontend/src/hooks/useKeyboardShortcuts.ts`.

## Non-obvious conventions

Grouped by area. The **landmines** (silent failures you'd otherwise miss) are the highest-value entries — preserve them when editing.

### Docker, tooling & tests
- **Everything runs in Docker.** Pyright/ty/eslint errors about missing modules in your editor are expected (deps live only in containers). Run lint via `make lint`.
- **`beat` depends on `web` health** in `compose.yaml` — without it `DatabaseScheduler` races `manage.py migrate` and crashes on an empty schema. Don't remove.
- **`ty` is advisory, not a gate.** It emits ~900 false-positive `unresolved-attribute` diagnostics on Django `.objects`/FK descriptors; CI runs it `continue-on-error`. The real gate is `ruff` + `pytest` + frontend `eslint`/`tsc` + `vitest`. (Makefile runs `ty check .` because the `web` container's WORKDIR is `/app/backend`; from repo root it's `ty check backend` — both correct for their cwd.)
- **All tool config lives in `pyproject.toml`** (`[tool.ruff]`, `[tool.pytest.ini_options]`); standalone `ruff.toml`/`pytest.ini` are gone. **`uv.lock` is committed** — Docker and CI run `uv sync --frozen`; regenerate with `uv lock` (host) when deps change.
- **Only `web`/`frontend` hot-reload.** `compose --watch` does NOT reload `worker`/`beat` — after adding/renaming a task module or `beat_schedule` entry, `docker compose restart worker beat` or it won't register/fire on the running stack (fresh `up`/CI unaffected).
- **Worker image carries chromium** for Playwright (~3–5 min slower cold builds); `web`/`beat` use the smaller image.
- **Integration tests are excluded by default** (`-m 'not integration'`); run with `pytest -m integration`. The Playwright render test passes only from the `worker` container (has chromium). E2E is six lanes under `e2e/` (`ui/api/ws/visual/a11y/perf`); journeys live in `e2e/ui/*_gold.py`. See `e2e/README.md`.
- **`MOCK_EXTERNAL=true`** (set by `compose.e2e.yaml`) short-circuits the Claude/OpenAI/Local/Schwab/Finnhub clients to canned fixtures (`apps.core.mocks`). **Never set it on the normal dev stack** — provider tests using `respx` will silently hit the mock instead. If you see "Mocked response" in `test_claude_streams_text_and_usage`, recreate containers: `docker compose stop web worker beat && docker compose rm -f web worker beat && docker compose up -d`.

### Backend wiring & security (landmines)
- **URL include ordering matters.** `config/urls.py` registers specific prefixes (e.g. `/api/costs/`) **before** generic `/api/` includes — a past regression routed `/api/costs/today` into the wrong app. Don't reorder without checking.
- **DRF serializers expose FK ids as `*_id`, not nested objects** (`thread_id`, `snapshot_id`, `parent_message_id`, …). Frontend TS interfaces must use the `*_id` key verbatim — `thread` vs `thread_id` silently reads `undefined`.
- **Security model is network isolation, not auth.** The stack binds `127.0.0.1` only; DRF defaults to `AllowAny` (no auth/permission classes) and there is no user token. WS is Origin-validated (`AllowedHostsOriginValidator` against `ALLOWED_HOSTS`). **Do not bind to `0.0.0.0` without first adding real authentication** — every API/WS endpoint is otherwise unauthenticated.
- **Encrypted secrets at rest.** Schwab OAuth tokens / provider API keys live in `ProviderConfig`/`ApiCredential`, encrypted via `django-cryptography` (key from `DJANGO_SECRET_KEY` + `/data/secret.salt`). Do not log these fields or expose them via DRF without `write_only`. Every read goes through the single guarded accessor `apps/secrets/credentials.py::decrypt_token`, which degrades to a skip on an undecryptable token (key/salt rotation) rather than raising `InvalidToken` mid-request. Keep the `ApiCredential` import where readers expect it — moving it breaks `<module>.ApiCredential` patch sites.
- **Prod `/` serves the SPA** via Whitenoise `WHITENOISE_INDEX_FILE = True` + a `TemplateView` catch-all in `config/urls.py` that excludes `api/|static/|render/|ws/|admin/`. Deep links work.

### Snapshots, images & rendering
- **Section terminal state is `"done"`; only the parent `Snapshot` uses `"ready"`** (landmine). Mixing them silently drops images — `_snapshot_image_ids()` filters `SnapshotSection.status="done"` (see commit `7acea371`).
- **Pinned snapshots reach the LLM as a synthetic first user turn** (landmine). `ThreadViewSet.create()` synthesizes a `done` user `Message` whose `content["text"]` is `serialize_for_ai(snap)` and `snapshot_ref=snap` (inside `transaction.atomic()` with a status-ready guard); `_build_request()` picks it up via the history query. Observer/trigger paths do the same per-fire (`apps/observer/services/run.py`). **Do not load the snapshot inside `_build_request()`** — the synthetic-message pattern keeps the pipeline provider-agnostic and gives the UI a visible record of what the model saw. Chart images attach separately via `_snapshot_image_ids()`.
- **Snapshot image bytes are offloaded to the `/data` volume.** New `SnapshotImage`s store bytes on disk (`file_path` on `app_data:/data`, `data` NULL) to keep `pg_dump` small; legacy rows keep in-DB bytes. **Always read via `apps.snapshots.image_store.read_image_bytes(img)`** (disk-first, DB fallback), not `bytes(img.data)`. Captures go through `image_store.create_image` (a volume-write failure degrades to in-DB rather than dropping the image). `DATA_UPLOAD_MAX_MEMORY_SIZE` aligns with the 5MB image cap → clean 413. Backup = DB dump + the `/data` volume.
- **`/render/chart` is deterministic** — URL params fully specify the render; `apps.snapshots.services.render.render_chart_png` captures it via headless chromium (`http://frontend:5173/...` in dev; hash-route on `index.html` in prod so the SPA is reachable via Whitenoise).
- **Snapshot diff:** `GET /api/snapshots/<id>/diff/?against=<other_id>` → `{delta, prev_id, curr_id}` (not yet surfaced in the UI).
- **`ChatMessage.content` is `str | list[dict]`** — a `"blocks"` key threads through as a content-block list (files/images/citations/tool_result), else as plain text.

### AI providers & capabilities
- **Tool use has provider parity; thinking/memory/files/citations are Claude-only.** All three providers run tools (Claude always; OpenAI/Local via a tool-call loop in `openai.py` emitting the same `ToolCallEvent`/`ToolResultEvent`, so `threads/tasks.py` and the WS consumer stay provider-agnostic). Tools are opt-in per profile (`enable_tools`); for OpenAI/Local also gated on `ProviderConfig.supports_tools` (default True; toggle off for endpoints lacking function-calling). Extended thinking (`enable_thinking` + `thinking_budget`, emits `thinking_delta`, billed as output), per-profile Memory (`enable_memory`, `/data/memory/<profile_id>/`, `AI_MEMORY_ROOT` to override in tests), the Files API, structured output, and news `search_result` citations are **Claude-only**. Enabling a Claude-only feature elsewhere is no longer a silent no-op: `run_ai_on_message` calls `apps.ai.capabilities.unsupported_features(...)` and, on gaps, writes a `system`/`done` `capability_warning` message + broadcasts a `warning` WS event, then continues (warn-and-continue). That kind is excluded from `observer_timeline` so it isn't miscounted as a cost-cap skip.
- **Add a tool** by registering a `ToolSpec` in `apps/ai/tools/registry.py`; each call writes a `ToolCall` row on the assistant `Message` and broadcasts `tool_call`/`tool_result` over `thread.<id>`. `Toolset.anthropic_tools()` / `openai_tools()` serialize the same registry to each provider's shape.
- **Anthropic Files API** — `apps.files.UserFile` proxies an `anthropic_id` + metadata. `POST /api/files/` uploads via `anthropic.beta.files.upload`; `POST /api/threads/<id>/attach-file/` adds a `document` block. Deleting a `UserFile` also deletes upstream; bytes don't live locally.
- **News citations** — `apps.ai.citations.news_to_search_result_blocks(items)` serializes news as `search_result` blocks with `citations: {enabled: true}`; the frontend `<Citation/>` resolves back to `news://<id>` or the original URL.
- **Multi-turn Claude caches the final prior message** — `RunRequest.cache_last_message=True` (auto when `len(messages) > 1`) attaches a second `cache_control` breakpoint; on hit, ~0.1× base input billing before the breakpoint.
- **Investigate mode** — `run_ai_on_message(investigate=True)` (+ `_apply_investigation_mode`) forces tools on for a bounded autonomous loop (`RunRequest.max_tool_iterations` via `AI_INVESTIGATION_MAX_ITERATIONS`) under a dedicated `AI_AUTONOMOUS_DAILY_CAP_USD`. Opt-in per fire via `EventTrigger.investigate` / `ObserverSchedule.investigate`; output tagged `kind="investigation"`.

### AI tokens, cost, caps & routing
- **Token counts are provider-aware.** `apps.ai.token_counter.estimate_tokens(text, provider=, model=)` routes Claude to Anthropic's `count_tokens` (lru-cached), else `tiktoken.cl100k_base`. Call sites omitting provider/model get the tiktoken default (back-compat); new code should pass them through.
- **Per-model payload budgets live in the catalog** — `ModelInfo.max_payload_tokens` (150k Claude 4.x, 200–300k GPT-5 variants). `serialize_for_ai` resolves the budget from `(provider, model)` when `max_tokens` isn't passed; raise it there, don't hard-code 40k.
- **Cost caps.** `apps.ai.cost.check_monthly_cap(provider, cap_usd, prospective)` sums the last 30 days of `AIRun.cost_usd`; a null cap is an opt-in no-op (daily cap mirrors it). Wired into `threads.tasks`, `observer.services.run`, `triggers.tasks`. Local-provider cost is hardcoded $0; cost caps/meters are hidden for local in the UI.
- **Cross-provider failover** (opt-in `AI_FAILOVER_ENABLED` + `AI_FAILOVER_PROVIDER`): if the primary errors **before emitting any token**, retry once on a secondary (must be enabled, have a `default_model`, and be within its own caps). **Never retries once a token has streamed** (gated on an empty `buffer`) — that would duplicate output. One `AIRun` records whichever provider produced the result.
- **Calibration-weighted routing** (opt-in `AI_CALIBRATION_ROUTING_ENABLED`): the router's fallback tier (`_calibration_choice`, *after* per-send override + profile pin) picks the best-measured enabled `(provider, model)` from recent `EvalRun`s (hit-rate desc, calibration-error tiebreak), gated by `AI_CALIBRATION_ROUTING_MIN_SCORED` / `_MAX_AGE_DAYS`, falling through to first-enabled. The query `.defer("_api_key")`s the encrypted column (else a key/salt rotation crashes routing).

### Observer, triggers & scheduling
- **Observer schedules drive Celery beat via `OneToOneField(PeriodicTask)`** — `ObserverScheduleViewSet.perform_create`/`perform_update` call `sync_periodic_task(...)` explicitly (no Django signals); beat picks up changes within its 5s sync interval. Cron evaluates in `OBSERVER_BEAT_TIMEZONE` (default UTC; set `America/New_York` for the UI's ET cron presets to be correct year-round).
- **Observer has three orthogonal opt-in modes** (all default False): `structured=True` (route through `claude_structured.run_structured` with the `ObservationReport` schema → `Message.content` as `{"kind":"structured_observation","report":…}`); `mode="diff"` (feed only `diff_sections(...)` delta vs the most recent prior ready snapshot, full payload if none); `use_batch=True` (Messages Batch, one `custom_id` per ticker; `observer.poll_open_batches` every 60s moves completed batches in; 50% cheaper, no streaming).
- **Observer response cache** (opt-in `OBSERVER_RESPONSE_CACHE_ENABLED`): a plain fire whose assembled prompt (coach+payload, keyed by provider/model) is byte-identical to a recent prior fire (within `OBSERVER_RESPONSE_CACHE_TTL_SECONDS`) reuses that observation (`kind=cached_observation`). Plain path only; the user turn stamps a `prompt_hash`.
- **Trigger backtest:** `POST /api/triggers/backtest/` replays the DSL over stored `OHLCBar` rows and returns match timestamps. Only `price`/`pct_change` leaves evaluate; live-only metrics (vix, position_pl) are silently absent from per-bar snapshots rather than raising.
- **NYSE market-hours** uses `pandas-market-calendars` (holiday/half-day correct, cached at module import in `apps.observer.services.market_hours`).
- **Market events are a forward calendar, not a session calendar.** `apps.market.MarketEvent` (earnings + curated US macro from Finnhub via `services/events.py`, refreshed daily by `market.refresh_events`) is distinct from `apps.market.calendar` (trading sessions). Reads go through `events.upcoming_events(...)` — used by the `days_to_earnings` trigger leaf, the opt-in `"events"` section, and `GET /api/market/events/`. Macro degrades to `SEED_MACRO_EVENTS` when Finnhub's economic-calendar isn't available.

### Thesis, post-mortems & calibration
- **Pre-trade discipline on thesis create:** `ThesisSerializer.validate` requires a non-empty `rationale` AND an invalidation (`invalidation_price` OR `invalidation_note`) **on create only** (existing theses edit freely; ORM creates / fixtures bypass). API-create payloads must include both.
- **Post-mortem objective verdict is deterministic — no AI key needed.** `apps.thesis.services.postmortem.objective_verdict(thesis, fwd_pct)` computes correct/incorrect/mixed/inconclusive from direction + actual `forward_return_pct` (off `OHLCBar` via `apps.market.returns`; DEADZONE 1%). The best-effort Claude narrative is layered on top and degrades silently to `report={}` on non-Claude provider / missing key / cap / any exception — it never raises out of `run_postmortem`.
- **Idempotent `scheduled→running` claim prevents double-billing:** `run_postmortem` opens with `PostMortem.objects.filter(id=pm_id, status="scheduled").update(status="running")`; a 0 result means already-claimed/done and it exits. Makes Run-now + beat safe to overlap. `THESIS_POSTMORTEM_HORIZONS=[7,30,90]`; `thesis.run_due_postmortems` runs every 300s.
- **Eval-driven calibration loop (`apps.aieval`)** replays a candidate `(system, model)` against the **frozen** source snapshots of decisive post-mortem'd theses and scores its directional call. **Look-ahead-safe: feed the model ONLY `serialize_for_ai(snapshot)`, never the coach/recall** (a coach block leaks post-trade info and inflates the score — keep that boundary). Results persist as `EvalRun` (`GET /api/aieval/runs/` + `/runs/latest/`). The scheduled beat (`aieval.run_scheduled`) is opt-in / default OFF (`AIEVAL_SCHEDULED_ENABLED`) — `run_structured` has no `MOCK_EXTERNAL` short-circuit, so an always-on schedule hits the real model (tests patch `run_structured` directly).
- **`DecisionJournalEntry` lives in `apps.thesis`, not `apps.threads`** — placing it in `threads` would create a `threads→thesis` import cycle. `JournalEntryViewSet` at `/api/journal/?thread=<id>`.
- **`get_or_create_review_thread(thesis)` uses `kind="consult"`** — exactly one review thread per thesis via the `Thesis.review_thread` FK (first call creates + saves; later calls return it without writing).
- **`apps/market/returns.py` is the shared price-path helper** (`nearest_bar_close`, `forward_return_pct`, `price_path_summary`); both analytics and post-mortems import from there. Don't inline these in callers.
- **`AgentPreset` builtins are seeded by a data migration** (`profiles/migrations/0005_seed_agent_presets.py`, four builtins via `get_or_create`). `builtin` is effectively read-only; conflicting/duplicate slug → 400.

### Analytics, Coach & scorecards
- **Analytics are on-demand, never scheduled** — nine services under `/api/analytics/` (`leaderboard`, `cpi`, `trigger_heatmap`, `observer_timeline`, `unusual_options`, `calibration`, `ai_calibration`, `trader_calibration`, `cohorts`), each a single DRF view aggregating off indexed columns at request time. No Celery tasks, no materialized views.
- **Leaderboard uses stored OHLC** — `provider_leaderboard(forward_hours=N)` correlates each `AIRun` against its snapshot's primary ticker (first `quotes` key) and `OHLCBar` at capture vs capture+N. Runs without a snapshot / `quotes` / price history show `coverage_pct=0` and `avg_forward_return_pct=None` rather than inventing a number.
- **Unusual-options** flags `OptionChainSnapshot` lines with `volume/oi ≥ 3.0` or `iv_z ≥ 1.5σ` over the 30-day chain-history mean; returns a per-line `triggers` list (a reasoning surface, not a scanner).
- **Observer timeline reads Messages, not a run log** — there is no `ObserverRun` table; the observer writes one Message per fire (assistant/done = success, assistant/failed = failure, system/done = cost-cap skip), grouped by day.
- **Scorecard** (`/scorecard`, `g k`) is the calibration surface: `calibration.py` aggregates `PostMortem ⋈ Thesis` into thesis-conviction calibration (hit-rate per bucket + Brier over `conviction→prob` = `0.5+(c−1)/4×0.4`, by-direction) + provider calibration (per-`(provider,model)` via `AIRun.message__thread`). `?horizon=` (7/30/90, default 30). `mixed` counts but `inconclusive` is filtered out (null `forward_return_pct`). Buckets are clickable → `.../calibration/drilldown/?conviction=&direction=&verdict=&horizon=` (same population, counts reconcile). A "Model eval calibration" section surfaces the latest `EvalRun` for `profile.default_model`, hidden when none has run.
- **The Coach** (`assemble_coach_context`, `apps/threads/coach.py`) injects `_calibration_block` (latest `EvalRun` for the profile's `default_model` + over/under/well-confident verdict), `_cohort_block` (setup-cohort base rate — hit-rate of *past* theses matching this call's direction/sector, excluding the current ticker), and `_distilled_lessons_block` (cross-ticker recurring lessons). All read **decisive, completed post-mortems only** (look-ahead-safe) and degrade via `_safe()`. `apps/lessons` clusters lessons by embedding cosine similarity (deterministic, no AI) in the daily `lessons.distill` beat; `Lesson` rows are mute/prune-able at `/api/lessons/`.
- **The Mirror** (`/mirror`, `trader_calibration.py`) joins `DecisionJournalEntry ⋈ Thread ⋈ Thesis ⋈ PostMortem ⋈ AIRun` into self-calibration signals (`decision_outcomes` — "you passed on winners N/M"; `conviction_reliability`), each drillable and **hard-gated on min-n** so a thin sample reads "insufficient history," not a verdict.
- **AnalyticsPage** is `/analytics` (`g a`, palette `go-analytics`); cards are self-contained and each call a `useAnalytics.ts` hook.

### Data sources, predictions & coverage
- **Free data sources + graceful fallback.** Beyond Schwab, `apps/market/services/` ships keyed/keyless clients (`alpaca`, `tiingo`, `twelvedata`, `polygon`, `tradier`, `fred`, `edgar`, `marketaux`, `treasury`); `services/fallback.py` routes quotes/OHLC/chain/news to a free provider when Schwab isn't connected, so the whole dashboard runs with no brokerage login. Keys are `ApiCredential` rows at `GET/PUT/DELETE /api/schwab/data-sources/…` (the `secrets` app is mounted at `/api/schwab/`), edited via the DataSourcesPanel on Settings → Connections. All reads go through `decrypt_token` (see Backend wiring).
- **Prediction Ledger** — `apps.predictions.AIPrediction` is the AI's own directional call (bullish/bearish/neutral + confidence + invalidation + horizon), **auto-extracted** from a structured `ObservationReport` by `services/extract.py` (zero added AI cost; returns `None` and never breaks the fire when there's no usable call). Dedup: ≤1 `open` per `(ticker, horizon, profile)` — a same-direction re-fire is a no-op (the call stays frozen-as-stated for honest calibration), a direction flip invalidates the old and opens a fresh one. Beat (300s): `predictions.resolve_due` (idempotent `open→resolving` claim then `direction_verdict`) + `predictions.check_invalidations`. Surfaced via `/api/predictions/ai-view/?ticker=` + `/divergences/` and the AI-calibration scorecard section; no dedicated page.
- **COVERAGE — a living per-ticker house view.** `apps.coverage.CoverageNote` (one per ticker — stance / conviction / bull_case / bear_case / key_levels / watching_for) is revised **with a reason** by `services/revise.py::revise_coverage` (one `run_structured(CoverageRevisionDraft)`) behind a **hysteresis gate** — it writes a `CoverageRevision` + updates the note only on `created OR draft.material_change OR a stance/conviction delta`, else just touches `updated_at` (reaffirm, no churn row); best-effort, returns `None` on no-key / cap / `InvalidToken` / AI-error and never breaks the fire. The observer auto-revises **by existence** — `hooks.py::maybe_revise_from_snapshot` queues `coverage.revise_from_observation` only when the snapshot's primary ticker already has a `CoverageNote`. `CoverageRevision.source_snapshot` is `SET_NULL` so snapshot pruning never deletes history. `/api/coverage/` (list / `<ticker>/` note+history / `<ticker>/revise/`); page `/coverage/:ticker`. **Gotcha:** a broad `coverage/` line in `.gitignore` (pytest/vitest report dir) silently swallowed `backend/apps/coverage/` from `git add` — kept tracked via a `!backend/apps/coverage/` negation. Any new app whose name collides with a common ignore pattern hits this.

### Frontend & runtime config
- **Frontend primitives** — reach for `Skeleton` / `SkeletonRows` / `EmptyState` / `ErrorBoundary` / `Toasts` (in `frontend/src/components/`) before ad-hoc loading spinners, "no data" text, or try/catch-in-JSX. Toasts need a `<ToastProvider>` ancestor (`AppLayout` provides one).
- **Command palette is Cmd/Ctrl-K** — `useCommandPaletteTrigger(cb)` registers the global handler; defaults in `AppLayout`'s `useDefaultCommands()` cover all top-level routes.
- **Notifications are user-anonymous in v1** — `Notification.user` is nullable, consumer subscribes to `user.anonymous.notifications`; switch to `user.<id>.notifications` everywhere when user-auth lands. The bell mounts in the shared `<TopNav>`.
- **Watchlist "what changed"** — `WatchlistDetail`'s per-ticker expander (`pages/watchlist/TickerChanges.tsx`) lazily fetches the ticker's latest snapshot diff vs the prior capture (only when expanded).
- **UI-configurable runtime settings** — `apps.core.SystemSettings` (nullable singleton, `.load()`, always `pk=1`); `runtime_config()` resolves each knob as `SystemSettings.<field> ?? settings.<DEFAULT>`, so a change applies without a worker/beat restart. **Sync-context knobs only** (retention windows, AI failover, observer response cache, scheduled-eval) — the async-ORM boundary keeps per-stream knobs env-only. `GET/PATCH /api/settings/` (PATCH a field to `null` clears the override); UI at `/settings/system`.
- **Local provider needs `host.docker.internal` + lists its own models.** `compose.yaml` maps `extra_hosts: ["host.docker.internal:host-gateway"]` on `web`/`worker`/`beat` so the backend can reach a host-run OpenAI-compatible server on Linux. The local model dropdown is **discovered, not cataloged**: `POST /api/schwab/providers/<provider>/probe/` calls `OpenAIProvider.list_models()` (`GET /v1/models`) — one call that connection-tests, compatibility-tests, and persists `ProviderConfig.discovered_models` + `models_synced_at`. **Do not add SSRF private-IP filtering to the probe** — local endpoints *are* on localhost/private addresses by design.
- **Dashboard rollup is fault-isolated per section.** `GET /api/dashboard/` returns five sections (theses / events / observer / triggers / briefing), each wrapped by `_safe(fn, default)` that logs and returns `default` on any exception. **Defaults MUST be full contract-valid shapes** (e.g. `{"armed_count":0,"latest_firings":[]}`, not `{}`) — a `{}` default crashes the SPA tile that reads `latest_firings.length`.
- **Morning Briefing** (`apps.briefing`) — `BriefingConfig` (singleton `.load()`) + `BriefingRun`. `services/assemble.py` gathers deterministic sections (open theses w/ price-vs-target, `upcoming_events`, overnight `TriggerFiring` + news, a `breadth`-only capture), each wrapped so it never raises; `services/run.py` posts a synthetic user `Message` into a `kind="briefing"` thread for best-effort AI synthesis. `briefing.run_scheduled` (every 15 min) fires once/day via a unique `scheduled_date` claim in `transaction.atomic()` (manual `POST /api/briefings/run/` is unlimited). Data sections render with no AI key.

## Testing

- **Unit** (pure logic): lots of these planned for condition evaluator, payload serializer, cost calc, market-hours, DSL parser, token estimator. Favor `pytest.mark.parametrize`.
- **Integration**: real Postgres via testcontainers (or CI services), `fakeredis`, Celery eager (`CELERY_TASK_ALWAYS_EAGER=True`). External APIs mocked at the SDK boundary with `respx` or `vcrpy`.
- **E2E**: six lanes under `e2e/` driving the full compose stack (overlay `MOCK_EXTERNAL=true`) — `ui` (Playwright journeys), `api` (httpx contract), `ws` (Channels events), `visual` (screenshot diffs), `a11y` (axe-core), `perf` (Lighthouse budgets, prod overlay). Design: `docs/superpowers/specs/2026-04-18-e2e-comprehensive-design.md`.
- **Frontend**: `vitest` + `@testing-library/react`. Do not duplicate E2E there.

### Quality gates (CI) — landmines

- **Architecture contracts** (`import-linter`, `[tool.importlinter]`): concrete AI providers (`apps.ai.providers.{claude,openai,local}`) are private to `apps.ai` (use `get_provider`/router); low-level crypto (`apps.secrets.{fields,keys}`) is private to `apps.secrets`. A *direct* import from elsewhere fails CI.
- **mypy is a real gate via a baseline ratchet** (`mypy` + `django-stubs`, `mypy-baseline.txt`): CI fails on any *new* error; the legacy backlog is baselined. `ty` stays as the fast advisory local checker. `strict_settings=false` (django-environ).
- **OpenAPI contract**: `backend/schema.yml` (drf-spectacular) is committed + drift-gated; `frontend/src/api/schema.d.ts` is generated (`pnpm gen:api`) + drift-gated — the single source for the `*_id` contract. `schemathesis` fuzzes every endpoint for 5xx under `MOCK_EXTERNAL` (e2e lane).
- **Coverage floors** (ratchet up): backend `[tool.coverage] fail_under=88`; frontend vitest thresholds 80/74/77/82. **mutation** (`mutmut`) runs nightly on the money paths (non-gate).
- **Property tests** (`Hypothesis`) cover the DSL evaluator / token budget / cost calc / market-hours. **`gitleaks`** scans staged commits + CI history.
- **Vibe-coding quality gates** (added 2026-06-04 — `make lint` runs the gating ones, `make quality` the advisory ones):
  - **`deptry`** (`uv run deptry backend`, gate): unused / missing / transitively-used Python deps. **Run after `uv sync`** (needs installed metadata to map `rest_framework`→`djangorestframework`); `uvx deptry` is noisy. Config in `[tool.deptry]`; `DEP002` ignores cover settings-string plugins (whitenoise, psycopg, …).
  - **`vulture`** (`uv run vulture`, advisory): dead Python code ruff's F-rules miss. Scoped to shipped code; framework-signature FPs live in `tools/vulture_whitelist.py` (excluded from ruff via `extend-exclude`).
  - **`ruff C901`** (gate): cyclomatic complexity, `max-complexity=15`; the 4 functions over it carry an explicit `# noqa: C901 (… do not extend)` — a ratchet, not a free pass.
  - **Semgrep landmine rules** (`tools/semgrep/rules/`, gate in `semgrep.yml`): CLAUDE.md silent-failures as executable rules (`bytes(img.data)`, `0.0.0.0` bind, `_safe(_, {})`, secret logging). Each has a `*.py` fixture with `# ruleid:`/`# ok:` annotations; `make semgrep-rules-test` validates them. The image-bytes rule exempts `image_store.py` (the sanctioned accessor).
  - **`type-coverage`** (gate): FE `any`-ratchet, floor `package.json:typeCoverage.atLeast` (99, measured 99.52%).
  - **`dependency-cruiser`** (`pnpm depcruise`, gate): FE architecture contracts — no import cycles + `src/api` must not import `src/{pages,components}` (the FE analogue of import-linter). Needs a **glob** (`'src/**/*.{ts,tsx}'`), not a bare dir. Dead-module detection is left to knip.
  - **`knip`** (advisory): unused FE files / exports / types / deps.
  - **Supply chain**: `pip-audit` + `pnpm audit` are now **BLOCKING** (were advisory). **`guarddog`** (advisory) scans PyPI/npm deps for malware / typosquat ("slopsquat") indicators. **`trivy`** (advisory, push-to-main only — skips PRs) scans the built web image for OS-package CVEs.
  - **N+1 guards**: `django_assert_max_num_queries` (pytest-django built-in; nplusone is Django-6-incompatible) pins query budgets on constant-query rollups — `apps/dashboard/tests/test_dashboard_query_budget.py`, `apps/analytics/tests/test_observer_timeline_query_budget.py`. Add one per new bounded aggregation.
- **Determinism + flakes** (landmine): `pytest-randomly` runs locally + nightly (`flake-audit.yml`), but the **per-commit gate (CI + pre-push) runs `-p no:randomly`** (definition order) so order-dependence can't red it. Tests use **`config.settings.test`** (InMemory channel layer) and **`backend/conftest.py`** autouse fixtures reset the calendar-resolution cache + channel-layer backends and set Hypothesis `deadline=None` — keep these; they fix real cross-test state leaks. **Known residual:** the `run_ai` async-streaming tests flake ~1/8 under random order — tracked by the nightly audit, not yet root-fixed. **Mechanism (diagnosed 2026-06-03):** `run_ai_on_message` runs `asyncio.run(drive())` and offloads ORM via `sync_to_async`; under some orderings a *prior* test leaves a DB connection closed, so an ORM **reconnect** executes on the event-loop thread, where Django's `@async_unsafe` guard raises `SynchronousOnlyOperation`. **Do NOT "fix" by setting `DJANGO_ALLOW_ASYNC_UNSAFE`** — that guard is load-bearing here: allowing the connect-under-loop to *proceed* corrupts the connection and cascades `OperationalError` (`db:5432`) into many later tests (observed *worse* than the single clean failure). A real fix must keep the streaming ORM off the loop thread / guarantee a healthy connection before `asyncio.run` (asgiref thread-sensitive executor × pytest-django connection management), not silence the guard.
- **Sentry** is opt-in (`SENTRY_DSN` empty → no-op).

Tests are expected to pass before commit. `make check` gates CI.
